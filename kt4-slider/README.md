# КТ №4. Слайдер на событиях мыши

Задание: используя события мыши, реализовать слайдер, который позволяет перемещать бегунок в заданном диапазоне (как `<input type="range">`). Над бегунком должно отображаться выбранное значение.

Решение оформлено как панель коррекции фотографии «Проявка»: шесть собственных слайдеров (экспозиция, контраст, насыщенность, температура, виньетка, зерно) в реальном времени меняют картинку слева. `<input type="range">` нигде не используется, каждый слайдер собран из обычных `div` и управляется через `mousedown` / `mousemove` / `mouseup`.

## Как запустить

Открыть `index.html` в браузере. Сборка, сервер и внешние библиотеки не нужны, страница работает и на GitHub Pages.

## Файлы

| Файл | Что внутри |
| --- | --- |
| `index.html` | разметка: превью (встроенный SVG-пейзаж и слои-эффекты), кнопки пресетов, панель с шестью контейнерами `.control` |
| `style.css` | тема, сетка, внешний вид слайдера (дорожка, заливка, бегунок, подсказка со значением), адаптив |
| `slider.js` | логика: создание слайдеров, обработка мыши, клавиатуры, касаний, применение значений к превью |

## Как описан слайдер в HTML

Каждый слайдер — это `<div class="control">` с настройками в `data`-атрибутах. JavaScript читает их и сам достраивает внутренние элементы, поэтому в HTML только настройки и подпись.

| Атрибут | Смысл |
| --- | --- |
| `data-id` | имя параметра, по которому слайдер находят при применении к картинке |
| `data-min`, `data-max` | диапазон значений |
| `data-step` | шаг, к которому значение «прилипает» |
| `data-value` | начальное значение, к нему же возвращает сброс |
| `data-suffix` | единица измерения в подсказке, например `%` |
| `data-bipolar` | двусторонний слайдер: ноль посередине, заливка идёт от центра, положительные значения показываются со знаком `+` |
| `data-ticks` | нарисовать под дорожкой засечки по шагу |

## Структура одного слайдера после создания

```
.control
  .control-head          подпись
  .slider                область перетаскивания, tabindex=0, role=slider
    .slider-ticks        засечки (если есть data-ticks)
    .slider-track        серая дорожка
      .slider-fill       оранжевая заливка выбранной части
      .slider-center     риска в центре (если data-bipolar)
    .slider-thumb        бегунок
      .slider-bubble     подсказка со значением над бегунком
```

Положение бегунка и заливки задаётся в процентах через `style.left` и `style.width`, поэтому слайдер остаётся правильным при любой ширине.

## Функции в `slider.js`

### Вспомогательные

- `clamp(value, min, max)` — ограничивает число диапазоном `[min, max]`. Используется, чтобы значение не вышло за края при перетаскивании за пределы дорожки и при нажатии клавиш.
- `snap(value, min, step)` — округляет значение к ближайшему шагу, отсчитывая от `min`. Так слайдер с шагом 5 никогда не покажет 37.
- `formatValue(value, bipolar, suffix)` — собирает текст подсказки: добавляет `+` к положительным значениям двустороннего слайдера и приписывает единицу измерения.

### `createSlider(root)`

Главная функция. Вызывается один раз для каждого `.control`, читает `data`-атрибуты, строит разметку, вешает обработчики и возвращает объект с текущим значением и методами `set` и `reset`. Все переменные и вложенные функции живут в её замыкании, поэтому у каждого слайдера своё независимое состояние.

Внутри неё:

- `render()` — переводит текущее значение в проценты и обновляет интерфейс: положение бегунка, текст подсказки, `aria`-атрибуты, заливку. Для двустороннего слайдера заливка начинается от середины и тянется к бегунку, для обычного — от левого края. Также ставит классу `.control` метку `is-changed`, если значение отличается от начального (подпись становится ярче).
- `setValue(next, silent)` — единственная точка изменения значения. Прилипает к шагу, ограничивает диапазон, и если значение действительно изменилось, перерисовывает слайдер и вызывает `applyPreview()`. Флаг `silent` используют пресеты, чтобы не пересчитывать картинку шесть раз подряд.
- `valueFromX(clientX)` — переводит координату курсора по горизонтали в значение. Берёт `getBoundingClientRect()` слайдера, считает долю от ширины (0…1) и растягивает её на диапазон `min…max`.

### Обработчики мыши (основная часть задания)

- `onMouseDown(event)` на `.slider` — начало перетаскивания. Проверяет, что нажата левая кнопка (`event.button === 0`), отменяет выделение текста через `preventDefault()`, переводит фокус на слайдер и сразу ставит значение по точке клика, поэтому щелчок по дорожке тоже перемещает бегунок. Затем подписывает `mousemove` и `mouseup` на `document`, а не на бегунок: курсор во время перетаскивания может уйти за пределы слайдера и даже окна, а документ события всё равно получит.
- `onMouseMove(event)` на `document` — само перетаскивание. Добавляет классу слайдера `is-dragging` (бегунок увеличивается, подсказка подсвечивается, анимации отключаются, чтобы бегунок шёл точно за курсором) и вызывает `setValue(valueFromX(event.clientX))`.
- `onMouseUp()` на `document` — конец перетаскивания. Снимает класс `is-dragging` и удаляет оба временных обработчика с документа, чтобы движение мыши вне слайдера больше ничего не меняло.
- `onDoubleClick()` на `.slider` — двойной щелчок возвращает слайдер к начальному значению.

Последовательность: `mousedown` → (много раз) `mousemove` → `mouseup`. Класс `is-dragging` ставится только в `mousemove`, поэтому простой щелчок по дорожке плавно анимирует бегунок к точке, а перетаскивание идёт без задержки.

### Обработчики касаний (дополнительно, для телефона)

- `onTouchStart(event)`, `onTouchMove(event)`, `onTouchEnd()` — те же действия, что у мыши, но координата берётся из `event.touches[0].clientX`. `preventDefault()` запрещает странице прокручиваться, пока палец двигает бегунок. Обработчики подписаны с `{ passive: false }`, иначе браузер не даст отменить прокрутку.

### Обработчик клавиатуры (дополнительно)

- `onKeyDown(event)` на `.slider` — слайдер получает фокус по `Tab` или по клику. Стрелки влево/вниз и вправо/вверх меняют значение на один шаг, с `Shift` — на десять шагов, `PageUp`/`PageDown` — на десятую часть диапазона, `Home`/`End` — к краям. Клавиши описаны объектом `actions`, где каждой клавише сопоставлено новое значение; если нажатая клавиша в объекте отсутствует, функция ничего не делает и не перехватывает событие.

### Применение к картинке

- `applyPreview()` — читает значения всех шести слайдеров и записывает их в CSS-переменные на элементе `#preview`. Дальше всё делает CSS: экспозиция, контраст и насыщенность собираются в `filter: brightness() contrast() saturate()` на SVG, температура — это слой тёплого или холодного цвета с `mix-blend-mode: soft-light` и прозрачностью из слайдера, виньетка — радиальный градиент с прозрачностью, зерно — слой с SVG-фильтром `feTurbulence`. JavaScript не трогает стили картинки напрямую, только числа в переменных, поэтому перерисовка дешёвая и идёт плавно даже при быстром перетаскивании.
- `markPreset()` — после каждого изменения проверяет, совпадают ли все значения с каким-то пресетом, и подсвечивает соответствующую кнопку. Как только пользователь сдвинул хоть один бегунок вручную, подсветка пропадает.

### Пресеты, сброс, сравнение

- `applyPreset(name)` — берёт набор значений из объекта `presets`, выставляет каждый слайдер через `set(value, true)` (без пересчёта картинки) и один раз вызывает `applyPreview()`. Бегунки при этом анимированно съезжаются на новые места.
- `onPresetClick(event)` на `#presets` — один обработчик на весь ряд кнопок (делегирование): через `event.target.closest('.chip')` находит нажатую кнопку и применяет её пресет.
- Кнопка «Сбросить» — вызывает `applyPreset('none')`, то есть возвращает все слайдеры к начальным значениям.
- `showOriginal(event)` и `hideOriginal()` — сравнение с оригиналом. На `mousedown` по кнопке «Удерживайте — оригинал» или по самой картинке добавляется класс `is-original`, который в CSS отключает фильтр и прячет слои-эффекты, и показывается бейдж «Оригинал». На `mouseup` или `mouseleave` класс снимается. `mouseleave` нужен, чтобы картинка вернулась, если кнопку отпустили, уведя курсор в сторону. Те же функции подписаны на `touchstart` / `touchend`.

### Запуск

В конце файла: для каждого `.control` вызывается `createSlider`, результат кладётся в объект `sliders` под ключом `data-id`; подписываются кнопки; вызывается `applyPreview()`, чтобы картинка соответствовала начальным значениям.

## Что в CSS отвечает за ощущение «живого» слайдера

| Класс или состояние | Эффект |
| --- | --- |
| `.slider:hover .slider-thumb` | бегунок слегка увеличивается при наведении |
| `.slider.is-dragging .slider-thumb` | во время перетаскивания бегунок крупнее, вокруг него оранжевое кольцо, курсор `grabbing` |
| `.slider.is-dragging .slider-bubble` | подсказка приподнимается и становится оранжевой |
| `.slider.is-dragging .slider-thumb`, `.slider-fill` | анимация положения отключена, бегунок идёт строго за курсором |
| `.slider:focus-visible .slider-thumb` | кольцо фокуса при управлении с клавиатуры |
| `.slider-fill` | заливка выбранной части, от центра для двусторонних слайдеров |
| `@media (max-width: 920px)` | панель переезжает под картинку, одна колонка |
| `@media (prefers-reduced-motion)` | все переходы отключаются |

## Почему так

- `mousemove` и `mouseup` вешаются на `document`, а не на бегунок: иначе быстрое движение мыши «теряет» бегунок, и перетаскивание обрывается.
- `preventDefault()` в `mousedown` убирает выделение текста и «перетаскивание призрака» элемента браузером.
- Все проценты считаются от `getBoundingClientRect()` в момент события, поэтому слайдер корректно работает после изменения размера окна и в адаптивной раскладке.
- Значения хранятся в замыкании `createSlider`, а не в DOM: интерфейс всегда перерисовывается из одного источника истины через `render()`.
